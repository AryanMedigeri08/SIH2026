# Optional enterprise planning

The `/wizard` page offers three starting points. Idea plus known investment opens
the existing seven-step wizard. The other choices run an optional planning preview
and prefill that same wizard after explicit acceptance. Registration, authentication,
the final create-and-analyze endpoint, financial formulas and DPR calculations are
unchanged.

## Trial inputs and results

- **Money, no idea:** compare six lower-cost starter businesses from the existing
  catalogue. Evaluate each against regional evidence and the full final feasibility
  pipeline. Return up to three distinct businesses, prioritizing sufficient own
  money, the existing appraisal status and regional evidence. When fewer than three
  fit, remaining cards show their cash gaps/concerns rather than claiming feasibility.
  This is a bounded shortlist, not an exhaustive search of all businesses.
- **Idea, unknown investment:** choose a supported business and describe the product
  or service. Compare the fixed low/mid/high outlay references, independent of own
  cash. Each trial uses the full final pipeline. An equipment quote produces one
  quote-based trial using the existing machinery/outlay allocation. A custom
  business requires a description, sector, type and equipment/setup quote; no
  unrelated business or invented supplier price is silently substituted.

`backend/app/data/planning_cost_references.v1.json` freezes the original catalogue
bands at `77afa90`. They are explicitly labelled planning estimates, not verified
BoQs or supplier quotes. Capacity, equipment, local prices, supplies and customer
orders still need confirmation. Changes to these references require a new version.
Machinery prices generated by the existing engine remain allocations of the given
budget; they do not independently establish the cost of a viable physical unit.

The preview adapter calls `feasibility._run_pipeline()` on a deep copy. It does not
call the separate financial calculator endpoint or the opportunity matcher's
approximate DSCR/loan screening, and it never saves a project or report per trial.
Sales, working capital, repayment, subsidy, SCA and appraisal figures come directly
from the existing pipeline. No new operating-expense, profit, payback or break-even
formula was introduced.

Regional evaluation uses the existing opportunity engine with an explicit business
intent, 5/10 km zones and source/evidence limitations. Missing evidence or service
failure is provisional. An engine-generated sales forecast or healthy DSCR cannot
prove local demand. The details panel exposes regional confidence, evidence gaps,
ODOP connection, assumptions and the existing financial output.

## Financial compatibility

The existing scheme margin and capital-structure margin can differ for some
category/gender profiles. Planning displays both, and asks the user to arrange the
higher contribution; neither original calculation is modified. Explicit zero and
unknown cash are different in the planning request. Affordability compares actual
cash to the returned contribution, so the original engine's zero-cash default cannot
make an unfunded starter appear affordable. Unknown cash becomes the selected
contribution only after the user confirms they can arrange it.

The accepted preview preserves project cost, turnover, contribution, premises and
loan terms on wizard mount. The legacy wizard's sizing path stays unchanged. New
planning paths use the machinery endpoint's `project_cost` parameter when resizing;
they do not change the existing helper's behavior for legacy applications. Explicit
zero rent survives the planning handoff. Cost/sector/capacity changes resume sizing,
and all edits are recalculated by the normal final appraisal.

The existing wizard/dashboard can show the capital-structure bank amount before
grant adjustment alongside a scheme-adjusted EMI. Planning labels its loan figure
as after scheme calculation. These existing views have not been reconciled by
changing financial logic.

## Preview lifecycle

All planning endpoints require the existing authentication dependency. Drafts are
owner-scoped, expire after 30 minutes, and are replaced by successful re-evaluation.
Acceptance requires acknowledgement of estimates and explicit acceptance of listed
concerns. It returns prefill data, never creates a loan application or saved business.
Only the ordinary final wizard submission creates the business.

Requests are bounded to six full trials (three for idea-only, one for a quote),
one in-flight request per owner, a ten-second resubmit interval and four in-flight
owners per process. Regional calls have a 45-second timeout. Full pipeline provider
timeouts remain their existing settings; a comparison can take several minutes.

Previews are intentionally ephemeral and process-local (up to 100 drafts). A server
restart, worker change or expiry requires re-evaluation and returns a clear error.
Use one worker/sticky routing for this preview lifecycle; a shared TTL store is
needed before deploying it across non-sticky workers. No database migration is
required. Refreshing the browser also resets the unsaved planning form.
